# 用三输入子电路的精确代价约束输出连接

## 问题与验收登记

上一轮的 0198 表明，只要已排除 XOR，相应的输出主输入连线就能较早消失。0189 的反例表明，先用 SAT 搜完整个 XOR 分支会增加成本。本轮保持冻结的完整 TCJAP 集成为基线，在同一输出连接上寻找可在第一次 SAT 决策前独立计算的活动度下界。候选分支始于已留档的 `9c9eef1`。沿用开发实例 0189 和 0019，并用旧轮的 0198 作回归。

设一个四输入内部信号在两个等大的八行集合上分别有 a、b 个 1。对每个收费门都有

    A16(a+b) = 2[A8(a)+A8(b)] + 2(a−b)²，Am(p)=2p(m−p)。

将两个集合分别取为某个输入等于 0、1，或两个输入相同、相异。限制后的每个原始输入均是常量、三输入变量或其反相。按行限制原电路即可得到两个三输入电路。常量、退化门和免费反相可以消去或通过重新标定下游操作吸收。移去门不会增加收费，输出免费，因而全电路的代价至少为两个限制函数独立最优活动度之和的两倍。十个合法二分的下界取最大值。不同二分会重复计费，不能求和。

TCJAP 的公开核按预算筛选计数。在一个主输入 H 被接到输出、另一端必须为最后一个内部门 G 时，本轮把 G 的整个实现锥也计入下界。在五种合法操作中枚举满足 op(G,H)=T 的归一真值向量 G；其中输出 XOR 时 G 唯一。每种选择至少花费 A16(G)+L(G)，其中 L(G) 是以 G 为免费输出时的下界。对所有相容的操作与 G 取最小值。若大于当前窗口上限，在原 CNF 中发布否定该选择的一元子句。独立的全目标下界 L(T) 超过上限时也可以排除整个查询。对两端都是内部节点的情况仍保留 TCJAP 原搜索。所有比较保留预处理和每个查询的成本。

DATE 第 III 节已有按门数和计数得到的下界。TCJAP 的公开核检查局部行、计数及剩余预算。电路复杂度中的变量限制与门消去已有先例，三输入真值分类亦已有先例。这些来源各自的目标、约束和此处的可检验区别不同。当前查新仅支持验证假设。方法能否作为原创贡献仍取决于直接比较、对既有方法的进一步核实及实际收益。[DATE 作者原文](https://www.cda.cit.tum.de/files/eda/2026_date_exact_synthesis_with_optimal_switching_activity.pdf) · [TCJAP 公开实现](https://github.com/qmkkk/TCJAP/blob/59e5a0e954d6a0a6711b2bdc9898db875ede6889/src/joint_relation.c) · [变量限制与门消去](https://arxiv.org/abs/2602.17942) · [按布尔链进行精确分类](https://msoeken.github.io/papers/2017_ismvl.pdf)

先独立生成并核验全部三输入最优值，在已证明的四输入实例、实际电路以及邻近的可行预算上检查下界。出现过度排除即修正。若有实际预算能够排除原核保留的连线，再接入冻结版。核心比较预先固定为基线、仅全目标下界、全目标与连接下界，在 0189、0019 上同核正序及逆序各测一次，每次上限 60 秒。判断依据为完整成本、正确性和新增排除。遇到反向实例保留原记录，同时检查当前剩余的主要耗时。在核心实验证据支持独立作用后再在独立例确认。
## 下界核验

三输入 128 个输出相位归一真值表均由独立状态枚举验证了上界可行和严格下界无解。208 个函数的 2080 种限制由另一种按变量赋值的程序核对，219 个返回电路及其中 77 个实际输出主输入连接都满足相应下界。0189 在四个主输入连接下的下界为 380、380、340、340，冻结传播在预算 300 的同一查询中对四条连接均未发现冲突。0019 的四个下界为 270、270、282、190，均低于其最优值 310，因此可预期有的函数受益范围较小。对 0189 的完整诊断另行让原 SAT 核逐项验证了 93 次排除，再运行正常求解取得 304。

从仓库根目录执行以下命令可复核下界和构建候选。数学核查和额外的 SAT 诊断各用独立进程。正式计时关闭诊断开关。

```powershell

gcc -O2 -std=c11 "$study/verify_cofactor.c" -o .local/verify-cofactor.exe
python "$study/audit_cofactor.py" .local/verify-cofactor.exe
python "$study/build.py" cofactor
python "$study/compare.py" 0189 .local/repeat-cofactor-0189 --cpu 10 --cap 60 --arms base cofactor-whole cofactor cofactor cofactor-whole base
```

## 完整时间和下一项检验

0189 的基线为 4.265、5.601 秒，带连接下界为 4.522、4.809 秒；0019 的基线为 9.770、9.393 秒，带连接下界为 9.652、9.057 秒。完整版本与仅使用全目标下界版本比较，两例的四对均有收益。相对冻结基线，0189 的两对方向相反，0019 的收益很小。这个局部差异有独立作用，未解决整体证明成本。

本轮全目标下界 192 和 112 都远低于已证明的 304 和 310。原因之一是把两片电路独立优化，完全忽略了相同的第一个收费门。从原搜索的第一层修正这一松弛。在四输入电路的前 d 个收费门已确定时，已付费用为其实际活动度之和；限制后的这 d 个信号可供剩余电路免费复用。每片的最小剩余费用由带这些免费信号的三输入搜索下界给出。加回已付费用后对十个二分取最大值，再对合法前缀取最小值。若目标能从当前已有信号经一个免费输出门实现，必须同时计入该短电路。重复真值的收费门可以接回已有信号，最优解至少有一个不重复的实现。

先独立检查 d=1、2 的下界是否严格提高，能否覆盖一个实际预算窗口，是否超过任何已知见证。全目标费用是偶数。将经验证的偶数下界作为作者模式 2 的起始活动度，仍由原程序建立 CNF、找到电路并完成剩余最优性搜索。使用冻结基线、仅用原余因子下界启动、用前缀修正后的下界启动，在同核按反序进行完整比较。预处理从每个新进程内部开始计时。若 d=2 的冷启动计算过重，保留计时并检验较浅前缀。继续以 0189、0019 为开发例；只有核心比较出现实际优势才进入独立例，独立例按 ABC 代表表中未用于开发的 0016、0017 顺序取用，各例固定 120 秒预算。此登记在前缀实现和计时之前保存。

# Reusing certified activity windows in pexact

本目录属于 DATE 2026 → TCJAP 独立复现的后续对照，使用原门库、目标真值与活动度模型。公开分支为 `codex/interval-proof-9720`。研究代码及实验只写入此目录。基础代码取本分支的初始提交 `afdbfca6d28e246b085e97d6da57f22ef0fd80b8`。

## 已有复现

完整复现本地冻结为 `365a8db35e39918d10e9a16cec1495611dd5e0d0`，与其公共历史镜像 `e1c19a7355b4d073280d57684d571f179fa8d717` 的文件树相同。根目录的 SOURCE_MAP.md、REPRODUCTION.md、THIRD_PARTY_NOTICES.md 提供源码映射、构建命令及许可。final-reproduction.zip 存放相对公共起点新增的三版 208 类原始结果、完整消融、独立审计及最终研究记录。压缩包内路径与冻结版一致。每例 300 秒，原版、强化版和重建版分别完成 67、72、80 类；历史参照为 71、73、94。原论文及作者核心分别见 [DATE 全文](https://www.cda.cit.tum.de/files/eda/2026_date_exact_synthesis_with_optimal_switching_activity.pdf) 和 [TCJAP 源码](https://github.com/qmkkk/TCJAP/tree/59e5a0e954d6a0a6711b2bdc9898db875ede6889)。

## 本轮研究登记

阶段 1–7 沿用冻结复现。阶段 8 只检验作者 mode 2 的一个调用链。PexaManExactPowerSynthesisBasePowerBDDBinaryInner 在得到 SAT 见证后缩小窗口，将门数循环从头开始；外层又按缩小后的步长推进。PexaManAlloc、ExactPowerSynthesisCnfBddRange 和 BSAT 的完整开销可能因此重复。阶段 9 假设针对固定目标、门库、输入数和收费门数，每个真正返回 UNSAT 的闭区间可为后续查询提供无解证据。另可用逐门支持度允许的折叠计数做整数加和，计算松弛后仍可能出现的总分。构造失败、求解 UNKNOWN 以及 SAT 未找到更低解均不能登记为 UNSAT。原算法已有逐窗口枚举，固定窗口的预算传播已在 TCJAP 中验证。跨迭代复用知识在增量 MaxSAT 中已有系统研究，本轮仅检验目标编码和折叠计数支持结合后的实际效果。[增量基数约束原文](https://arxiv.org/abs/1408.4628)

阶段 8 最小诊断先采集 0189 冻结代码的窗口、门数、状态与耗时。如果真实轨迹无重复证明且可实现分值无法排除窗口，就保留负结果。若有可排除工作，先枚举核验，再在相同入口验证。主要指标是完整最优求解的墙钟、固定上限完成数和独立见证。按同一逻辑核心、ABBA 反序比较 0189、此前比强化基线慢的 001e、以及编号相邻的 018b。前两例各限 30 秒，困难例各版 300 秒；困难例用两版各一次轮换。记录包括超时、不利实例和相同结果的重复性。候选初筛后再决定扩展规模。作者的全量复现数据已冻结。

从实际轨迹到第 12 阶段。0189 原有 41 次窗口查询。按前 g 个门的可用支撑计算可达分值，19 个窗口为空；另有 7 个窗口的剩余分值已由之前同门数的 UNSAT 查询覆盖。诊断版在这两组分别用了 0.094 和 0.279 秒进程时间。第一候选按原顺序跳过这 26 个窗口，其余 15 个照常进入原流程。两种条件分别有开关。独立枚举在 144000 次顺序查询中没有发现误排；对编译后两个代表例的实际跳过行为逐项复核，最优值 304、32 与冻结独立证明一致。0189 两对完整墙钟从 1.734、1.711 降至 1.364、1.383 秒。001e 的反序配对方向不一致。原始长例继续按预登记执行。

下一候选登记。原版在 0189 上三次调用 SAT 得到满足解，原程序每次缩窗后重新寻找可行电路。尝试保留第一个可行电路及其代价 U，然后仅对各收费门数中未被排除且低于 U 的可能活动度求证。一次查询覆盖该门数的最小、最大未决分值，UNSAT 覆盖整个该区间，SAT 使 U 严格变小。所有门数都没有更低可能分值时返回保存的电路。实际支撑至少三输入排除零收费门的可能，最大门数由原编码对象上限和每个非常数门的最低收费限定。属于分支定界和已有证据的工程复用。遇到编码构造失败或 UNKNOWN 时释放临时对象并交还原程序，不对未决查询宣告无解。仅在 0189、001e 上先作与第一候选的反序配对；每条完整证明的未决集由独立脚本重算。有效再在未用于设计的函数上确认。

三个跟踪用例都在第一个见证上完成了证明，尚未覆盖“找到更低的见证”这一代码分支。为核验该分支及失败回退，使用确定性小型求解器替身，在已知所有可行分数的小空间逐个比对最终最优和对象所有权，并注入 UNKNOWN、构造失败和分配失败。三次真实证明对全部允许门数重算后均无剩余更低分值。001e 的 224 也用独立电路枚举排除了更低值，共访问 979 个状态。

第二候选在同一小例比较中，0189 的第一候选为 2.924、2.877 秒，保存见证的第二候选为 2.484、2.516 秒。001e 的第二候选为 0.498、0.424 秒，第一候选为 0.744、0.476 秒。两个实验组的系统负载和测量时段不同，跨组原始秒数不用于推算加速。800 个已知真实解集的模拟测试覆盖了 367 次改进原见证的严格证明、147 次分配失败、142 次编码失败和 144 次未知求解状态；每次均核对返回对象、活动度及回收。第一候选在困难例 018b 的 300 秒内未完成。原版对照正在按预登记运行。困难例再用第二候选在同一 CPU 做一次 300 秒对照。

独立确认预登记。以冻结的 TCJAP 耗时划分四层，每层用预定哈希选择 3 个未参与设计的函数，具体编号和交替顺序见 evidence/confirmation-plan.json。原版重建与保存见证版本在同一核心配对，每例每版 30 秒。报告共同完成的几何平均比、超时截断总成本、增减完成与反向实例。此面板检查独立效果的可转移性；只有 208 类同限时数据才支持全族 300 秒覆盖主张。当前主机也有其他对话的独立任务，进程固定核心、逐例顺序运行，主机共享负载是计时限制。

## 复跑入口

从本分支根目录依 REPRODUCTION.md 还原三份固定来源并构建 joint 二进制。`BASE` 表示已经构建该冻结版本的仓库根目录。本目录的构建仅从 BASE 读取源与对象文件。首次运行使用新的结果标签；每个标签保留实际命令、哈希、CPU、退出状态、时间及输出。

```text
cd research/interval-proof-9720
python build.py BASE
python build.py BASE --saved
python check_windows.py
gcc -std=c11 -O2 check_saved.c -o .local/check/check_saved.exe
.local/check/check_saved.exe
python paired.py BASE 0189 ABBA new-0189 --cpu 20 --cap 30
python audit_windows.py evidence/filtered-0189/solver.log
python audit_certificate.py evidence/saved-0189/solver.log evidence/saved-001e/solver.log evidence/saved-xor3/solver.log
python verify.py
```

paired.py 的 A 为冻结 TCJAP，B 为允许分值加历史无解记录，C 在 B 上保留可行电路并证明严格下界，D/H/O 分别为仅分值、仅历史、关闭两个条件。统计实验均关闭详细跟踪。每次新进程自行承担构造可达分值集合及求解的全部成本。check_windows.py 与 check_saved.c 服务于正确性检查，求解时无需运行。confirm.py 读取已登记的编号和顺序，在预设三核心执行已登记面板；本文记录的原始行保存在 evidence 中。
